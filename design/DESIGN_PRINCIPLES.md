# Echidna Web 设计原则

适用于本轮 Echidna Web 设计稿及后续交互原型。

## 核心交互：Agent 生长画布

画布是主界面，创建 Agent 是基本操作，如同绘图工具中创建一个图形。Agent 根节点承载订阅接入、账户登录、模型、任务与人格配置；配置完成后，随着任务执行，由根节点向右逐步生成行动、工具调用、结果与可记录的决策分支。

- 每个 Agent 从自己的根节点生长；新增节点延伸路径，不重新排列已经形成的历史。
- 画布支持平移、缩放、拖动根节点和按需跟随。用户检查其他区域时不抢走视角。
- 主画布使用独立人物作为 Agent 本体，只保留名字与极少的状态标记，不在人物下方重复放置信息卡。任务、模型、人格与运行操作收进点击人物后的对话详情。
- 临时连线表示向另一个 Agent 请求协助。明确问题、随附材料和方向；不自动共享全部上下文。
- 协作区分待接收、处理中、已回传与结束连接；已产生的记录保留，结束连接不伪装成任务撤回。
- 路径根据实际记录生长，不把逐字输出或假设中的内部思维绘成事实。概念原型必须标明模拟登录与模拟执行。

## 图像优先

**能用图像展示的就不要使用文字。**

凡能通过图形、空间关系、路径、形状、对比或动效清晰表达的信息，必须采用相应的视觉表达，不再用说明文字代替或重复。把大段文字排成卡片、截图或绘制成图片，不算图像化表达。

这里的图像以**逻辑流程图**为主：用节点、连线、分支条件与状态呈现关系。不要用拟物插画、场景装饰或物品隐喻代替流程结构。

## 决策与执行的视觉表达

| 内容 | 表达方式 |
| --- | --- |
| 决策过程 | 展示候选路径、相关证据、选中路径及其他路径的状态变化，让用户看见什么改变了选择。 |
| 证据与结果 | 通过并置、差异标记和前后变化呈现比较，保留可展开的来源。 |
| 工具调用链 | 展示调用顺序、串并行关系、依赖、运行状态与结果回传。 |
| 指令派发 | 展示发起者、接收 Agent、派发流向及接收状态，并与工具执行命令区分。 |
| 历史探索 | 用可展开的路径和时间回放保留关键转折；首屏聚焦当前决策。 |

## 文字的用途

文字用于必要的名称、短标签、精确数值、命令与参数、原始输出，以及图像无法准确表达的简短解释。长说明和原始记录按需展开，不能承担主画面的主要信息传达。命令及原始内容保持可选中、可复制。

状态不能只靠颜色区分，应同时使用形状、位置或必要的短标签。执行结束、结果回传和结论成立必须分别表达。

## 设计评审

- 去掉解释性长段落后，仍能看懂当前选择、影响选择的证据和下一步行动。
- 图形表达具体关系，不用装饰性节点、连线或动画制造复杂感。
- 已能用图像讲清的信息，不再附加同义说明文字。
- 视觉中未能表达的关键含义，应改进图形结构或补充必要短标签，不让用户猜测。

## 图表视觉语言

参考 [diagram-design](https://github.com/cathrynlavery/diagram-design) 的编辑式图表感觉，保留下方指定配色。

- 以最新 Excalidraw 截图为界面壳层参考：连续的纸面、充分留白、悬浮圆角工具栏；去掉贯穿页面的顶栏与底栏分隔线。只在工具浮层和临时设置面板使用很轻的阴影。
- 衬线字体用于品牌与旁注，易读无衬线字体用于名称和任务，等宽字体用于编号、技术标签与命令。Agent 使用柔和圆角，靠间距组织内容，去掉内部贯穿格线。
- 保留 diagram-design 的图形语义和排版层级：起止胶囊、行动圆角矩形、柔化判断菱形、材料纸页、无框旁注和浅虚线分组；轮廓可有轻微手绘感，不影响端点定位和阅读。
- 一张图聚焦一个问题，首屏至多约 9 个节点；细节按需展开。
- 仅强调 1–2 个关键元素，优先用于当前判断与执行中的命令。
- 连线采用规则的直角或小圆角转折；分支出口标明条件，标签留白遮罩避开线条，避免交叉和穿过无关节点。
- 已发生、未走路径和等待结果保持明确区别；只展示可记录的依据、决策摘要和行动，不把推测绘制成真实内部思维或已成立的结论。

## Web 白板与画笔

- 左上角切换、新建、改名画布；各画布独立保留 Agent、手工图形、协作关系、视角和底纹。原型只在本次打开期间保存状态。
- 顶部悬浮图标栏抽象为画笔：选择、漫游、Agent、行动、判断、材料、连线、区域、批注、自由画笔和橡皮。短名称通过提示与辅助标签呈现，不把功能清单铺在画布上。
- 默认空白暖米纸，支持方格、点阵、空白三种底纹；底纹是画布属性，切换底纹不改变图形。
- 左上角菜单按钮和画布名称使用透明背景，避免遮挡后面的内容；文本输入只保留单层焦点边框。菜单、详情和弹窗支持点击外部收起，文件草稿仍经过未保存检查。
- Agent 画笔先放置，再设置订阅、模拟登录、模型、任务与人格；设置面板按需出现。
- 手工绘图属于用户草稿；执行路径属于 Agent 记录。撤销、重做和橡皮作用于手工图形，不伪造、擦除或撤回已发生的执行。
- 连线两个 Agent 创建临时协作；连线两个草稿图形表达关系。自由笔迹和关系线本身不作为关系端点。
- Docker／通用 MCP 使用独立小图标与短名称，地址、认证和工具目录按需展开。连到 Agent 后先确认配置，再由持久化绑定绘制版本线；同一接入可跨项目连接，图标拖动不改变权限。绑定确认与工具就绪分别呈现，密钥不进入画布或标签。
- 创建入口用 harness 图标卡和带图标的列表选择模型与项目，按实际能力生成默认配置；名称与形象细节折叠，避免必填项与原生参数铺满主画面。
- 绘画、拖动或漫游时关闭自动跟随，避免执行进度打断用户操作；后台画布的进度不切换当前画布。

## 模型轮次与决策图

- 自动生成的画面按模型响应与执行事件展开，不再套用固定的「材料→判断→行动→结果」配方；手工画笔仍可绘制流程草稿。
- 每次模型调用形成一个可展开的局部记录，包含实际交付的可见摘要、明确记录的候选方向与所选方向、工具调用和回传。没有返回摘要或候选项时，不补造内容。
- 模型输出完成、工具执行完成与结果获得验证分别表示。工具可以并行发起、按实际顺序回传；工具结果进入后续模型调用后，才能展示该次调用返回的新摘要。
- 摘要和面向用户的回答在原位置流式补全，不将每段文本或每个 token 画成新节点。逐轮导航、事件回放和原始事件按需查看。
- 决策图以依据汇入、选择分支和工具反馈为核心；主画布使用短标题、图形与人物，完整摘要、参数、结果和来源引用点击展开。
- 展示结构由前端保证：材料在上、判断居中、候选方向与工具记录在下。模型提交任务语义和明确引用，不负责坐标或美术；不能要求模型靠长篇自然语言“画好图”。阅读小节不冒充真实采样步骤，也不根据相邻位置推断工具依赖。
- 默认只显示进展和局部选择分支；长距离依据线在点选、聚焦或悬停时按直接引用展示，并用必要的短标签解释含义。短虚线只表示未选方向，不能同时承载多种含义。
- 命令在画布上使用独立工具轮廓、简短名称、有限的命令字面预览与状态符号，完整命令、工作目录、原始输出及回执分层展开。工具身份与状态分别呈现，不能只剩一个“成功”圆点。
- 自然回复以 Markdown 纸面摘录直接可见，细绿左边、暖纸背景、衬线标题；支持列表、表格、引用和代码块，通过「展开回复」看全文。保持完整 Markdown 原文，通过可见区域收起，不按字符截断语法；链接与展开操作分离。没有结构标注的普通对话也应有实际回复，不补造决策。Fixture 在角色与回合旁标为离线／固定示例。
- 运行时参考最新疏朗画布：目标、观察与选择用无框衬线标题，材料是上方短标签，候选项为轻胶囊，工具是终端圆形落点与独立状态角标。柔化菱形保留给手工画笔，不要求每个运行时判断套框；只有结论与实际回复保留有限纸面摘录。
- 每个标题上方至多常显两项实际引用，多余依据通过数量入口展开；细弧线汇入标题。引用入口导航到原节点，不生成材料、工具或事实副本。完整跨片段依据线只在聚焦时显示，以小圆角绕开工具、候选项与材料入口。
- 回合高度按实际内容和可聚焦引用范围计算，减少简单对话的空白。实际回复在已出现且尚无工具的结论下方落位，减少独立空列；后到工具另开片段，不能为了连线或压缩排版移动已有节点。
- 按用户最新约定，附加提示只包含工具用法，不追加风格、流程或任务指导。图形结构由前端根据实际记录呈现，缺失的候选项和依据不由显示层补造。
- 用户纠正会追加带来源的新路线，已有路线的事件与位置保持不变。演示回放与真实 Provider 记录必须清楚区分。

## 对话与路线纠正细则

- 真实对话中的用户消息可从发送前创建上下文分支，已结束回复可从本回合之后创建；新角色由细绿实线及分叉圆点连接来源。后续记忆不继承，原路线可继续，文件与外部状态不回滚。以下建议采纳／暂停规则描述离线纠正演示，不代替真实原生分叉。

- 点击角色、Agent 上的对话按钮或具体节点开启对话；面板保留 Agent、路线和节点的来源。
- 对话先生成可编辑的建议。用户采用建议后，才从对应来源长出新路线；未采用建议可以重新选择，不因关闭面板丢失。
- 原路线、已派发的命令、已有工具结果及其位置保持不变。暂停旧路线的后续演示，新路线用鼠尾草绿和分支结构体现变化。
- 隐藏历史仅改变视图。任务更新同样产生新路线，不覆盖已有执行记录。
- 菜单容纳画布新建、复制、改名、切换，手工图形编辑，历史显示、角色动画、跟随和暂停等常用功能。

## 人物形象

- 人物指二次元拟人角色，可在完整立绘和 Q 版之间切换；不是品牌图标或字母标识。
- Echidna 按 2026-10-18 用户最新要求，使用 Re:0 爱姬多娜黑发 Q 版同人形象：黑洋装、白蝴蝶发饰；黑发为用户指定改色。九姿态保留公开事件对应的思考、材料查阅、方案比较、电脑操作及报告交付。旧现代服装立绘保留为历史素材。DeepSeek、Claude 保持既有灵感拟人设计，不宣称为厂商官方角色。
- 外观、模型、任务和人格独立设置。选择外观不会更改接入账户，也不暗示模型能力。
- 点击人物打开对话，任务与角色详情默认折叠；拖动人物改变位置，操作按钮留在详情内，画布不常驻一圈功能按钮。
- 待命、思考、工作、递交报告优先由对应人物姿态表达，减少状态卡和文字。已发生的工具调用、依据与路线转折仍保留可展开记录，动作不替代事实。
- 轻量动效可关闭并尊重系统减少动态设置。人物表情本身不代表执行失败或结论成立。
- 角色服务于身份识别和沟通，画布仍以逻辑路径为主，不堆叠场景插画。
- 创建 Agent 时先选角色形象，再设置接入、任务与人格。流程旁可显示同一角色在当前步骤的动作，只保留一个当前动作形象，不在每个历史节点重复摆放人物。
- 点击流程旁的人物查看该步骤的记录；主人物仍作为对话与详情的入口。Echidna 的九姿态按公开标注、工具生命周期、流式回复及终态切换，打开对话不覆盖执行动作；DeepSeek Q 版仍沿用四姿态。查看旧记录只改变主人物的查看姿态，步骤旁人物保留当前前缀的执行动作。

## 项目文件入口

- 使用 Re:Zero 碧翠丝的同人角色形象作为项目档案管理员，主画布只显示独立人物、书与「项目档案」短名称。她是文件入口，不自动创建或运行一个 Agent。
- 默认抱书待命；点击后切换为翻书姿态，同时展开文件树与文件预览。关闭文件预览或进入其他详情后回到抱书姿态。保持透明背景，不添加书架、室内场景或常驻文字卡。
- 2026-10-18 实现已接入当前工作目录的真实文本文件，点击角色打开模态文件窗口，提供编辑、显式保存及历史内容对照。沿用原有九色；桌面左右并置，窄屏上下对照。记录从首次读取开始，区分手动保存和读取快照。角色是访问入口，不把文件存在、材料被读取和证据得到验证混为一谈；早期设计中的硬编码样本不再作为当前文件内容。
- 修改记录以连接图呈现，碧翠丝是根，文件和版本沿记录顺序向外延伸；角色与整条文件路线共同拖动，不额外放置第二个同名角色。保存与读取观察使用不同图标及实／虚线，缺少事实的分支不补画。版本节点只保留版本号、动作与时间，点击再看内容和哈希；主画布与文件窗口复用同一版本图。

## 运行交互细则

这些规则用于 Echidna Web 编排与画布设计。当前原型使用本地演示事件，不代表真实模型、进程、计费或持久化后端已经接入。

### 一步、轮次与连线

- 一轮对应一次模型请求及其关联记录。文本、摘要和工具参数可在这一轮内流式增长；同一轮可以没有摘要、没有选择、包含多个工具调用，或只有回答。
- 模型输出完成与工具完成是两个事件。工具回传进入后续模型请求后，才能出现由这些回传引发的新模型摘要；不能把后续判断插回上一轮。
- 连线具有固定语义：响应先后、依据引用、执行依赖、结果回传、任务派发、路线纠正。普通顺序线不声称因果；实线、点线、虚线及短标签结合使用，颜色不是唯一标记。
- 选中决策时突出其直接依据、所选方向及后续引用该决策的记录，其他内容淡化。选中、缩放和展开不改写记录或重排已经落位的历史。

### 决策与来源

- 每份决策必须带 actor、所在轮次、事件序号、依据引用和来源类型。候选方向只在模型明确返回或操作者明确提出时显示。
- 当时的决策记录、后续的新决策与事后评估分别追加。不得用最新答案覆盖旧理由，也不得将事后总结显示为模型当时已知的内容。
- 每轮保留输入快照引用：任务、人格指令、模型接入配置引用、能力声明版本、材料版本以及继承的上下文来源。快照不携带凭据。
- 模型响应、工具观察、用户材料、派生摘要和验证结论分别标注来源。工具退出成功、结果收到、结果采纳和结论成立不是同一事实。

### 流式调用与结果

- 工具调用分为参数接收、参数完整并校验、派发、运行、结果回传。参数未完整时不显示“执行中”。未开始执行的拒绝不伪造执行回执。
- 记录 call_id、实际参数、起止事件和真实回执引用；长结果按需展开，完整原文保持可复制。截断预览不能代替原始结果。
- 多个调用可并行，按实际接收顺序记录回传。串并行和依赖由明确记录决定，不能仅从空间位置推断。
- 模型错误、工具错误、事件连接错误和执行结果未知分别呈现；失败保留阶段和原因，不生成成功结果。

### 用户介入与停止语义

- 补充事实追加到选定来源；改变目标追加新路线；两者都保留 source_agent、source_route、source_node、source_event_seq。
- 暂停后续采样只阻止下一次模型请求，已经派发的工具仍可能完成并回传。请求取消是独立操作，直到执行器明确确认前，仍显示“取消待确认”。
- 请求取消后收到真实完成结果时保留该结果。不能因为暂停、断线、关闭页面或切换画布，就宣布工具已停止或副作用已消失。
- 未知执行状态需要对齐原执行资源与回执；禁止为了恢复画面而重新派发命令。恢复后是否继续采样按现有运行时的明确恢复约定处理。

### 子 Agent 交接

- 委派记录固定包含父 Agent、来源轮次、具体任务、完成条件、材料快照、结果接收者和共享预算引用。默认只传选定材料，不复制整个父会话。
- 创建请求、创建回执、任务接收、工作中、结果回传、主 Agent 采纳分别记录。创建工具返回 agent_id 只证明子 Agent 已创建。
- 子 Agent 使用独立 Session、工具调用 ID 和 Provider 状态；父会话只通过明确消息与材料引用接收结果。跨 Agent 的图形连接不自动共享完整上下文。
- 回传保留子 Agent 来源、材料版本、证据与限制。采纳必须带采纳者和采纳范围；可以采纳定位事实，同时保留实际影响尚未验证的限制。
- 人格、角色外观、模型与任务独立。点击子角色可以查看它自己的记录，并能从交接详情返回父任务。

### 文件、资源与冲突

- 文件用 path + revision / hash 引用；读取材料和后续修改不能只依赖可变路径。碧翠丝的档案区分当前文件、历史版本和任务引用的快照。
- 展示实际记录的读取者、修改建议来源和基础版本；没有读取回执时不声称某 Agent 已读过文件。
- 多 Agent 修改同一资源时，接入层需要明确工作副本隔离或串行写入归属。提交前核对基础版本；不匹配时返回冲突，保留双方差异，不静默覆盖。
- 原型中的修改建议比较是只读演示，不写入真实项目。任务里的“只读核对”是工作约定，实际执行权限仍由现有运行时负责，不由角色或连线隐式扩大。

### 历史、视角与密度

- 历史查看绑定 Agent、路线和确切事件序号，使用那个前缀重建画面。后续摘要、选择、子 Agent 和采纳状态不能泄漏进旧快照。
- 查看历史或阅读其他位置时继续接收后台事件，但保持快照、选中项与视角不变，只提示新增记录数量。返回实时必须是明确操作。
- 图形位置是独立视图状态；折叠、展开、过滤与缩放不改执行事实。远看角色、任务与转折，近看局部决策，点击看参数和原始记录。
- 长任务接入时按可见区域与事件区间加载；保留节点坐标和稳定引用。图形虚拟化不能删除事实或改变关联。

### 恢复与幂等

- 后端事实记录与浏览器视图状态分别保存。真实刷新恢复需要同一 Session 的快照和连续事件后缀；当前原型只演示事件连接恢复，不声称具备真实重启恢复能力。
- 事件用稳定事件 ID 和有序游标去重、补齐；创建命令用 command_id 返回同一创建回执。重复交付不得重复创建子 Agent、执行工具或累计用量。
- 复制画布应区分复制视图与启动新任务。历史仍指向原始执行来源，不能把复制行为当作已重新执行，也不能不经恢复校验就续跑真实会话。
- 断线后先同步事实，未知执行结果继续保留为未知；是否恢复模型采样与是否重新执行工具是两个不同决定。

### 模型能力与预算

- 能力来自实际接入配置和协议回传，不根据人物、人格、供应商品牌或模型名称猜测。未声明、未返回和明确不支持分开表达。
- 启动前预填版本化操作契约、正式 Tool Specs 与精简环境状态；子 Agent 由编排层注入对应能力、身份和边界。压缩或恢复通过既有上下文构建器重建当前约定，保留历史原文。
- 子 Agent 共用明确的并发 / 总量、层级与预算边界。创建前完成原子准入；创建被拒绝时保留可解释的拒绝记录，不伪造 Agent 或自动绕过边界。
- 新委派被拒绝只阻止该次创建；已经派发的其他工具仍可回传。画布分别显示“创建未派发”和真实执行结果，不因配额限制丢弃已有回执。
- 用量按 Provider 实际回传统计；缺失时显示未提供。额度、客户端准入次数、Token 用量、预估费用和实际费用分别表达，不相互替代。

### 人物与可访问性

- 待命、接收输出、操作、等待工具、递交结果对应可确认事件；错误、取消待确认和结果未知使用独立短标记与详情，不能只靠人物表情或颜色。
- 人物动作、呼吸与过渡可关闭并尊重系统减少动态设置。静态形象模式仍保留全部操作和状态。
- 主要操作提供可访问名称；窄屏可从菜单进入档案、运行控制与交接详情，不依赖角色始终位于可视区域或依赖悬停。

### 本轮验收场景

1. 工具反馈改变判断：先保留两个解释，并行检查；两份回传进入下一轮，明确选择最小复现与独立复核，旧决策不被覆盖。
2. 用户中途纠正：从指定事件前缀发起对话；新路线绑定来源与新输入快照，旧路线、命令和位置保留，暂停与取消分别处理。
3. 委派与采纳：创建回执后出现子角色；子会话只接收选定材料，独立工作、回传，主 Agent 再明确采纳有限范围。
4. 历史与后台事件：固定旧快照，继续接收新的轮次与子 Agent 事件；旧快照不变，新增计数增长，主动返回实时后才显示新内容。
5. 中断与失败：模拟连接中断后不生成取消结果；恢复游标去重且不重发命令。工具失败保留错误和回执，不生成后续成功结论。
