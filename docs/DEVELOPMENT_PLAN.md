# 开发计划

## 目标与交付顺序

第一版交付一套本地 Web Agent 工作台：在无限画布上创建角色，绑定实际支持的账户与模型，设置任务与工作偏好；执行过程中按可观察事件生长路径，支持对话纠正、有限委派、版本化材料和可追溯的结果采纳。

阶段按验收门槛推进，不以界面是否“看起来完成”作为完成依据。P0 归档现有设计；P1 完成可维护的离线画布；P2 先证明运行时桥接；P3 才接入一条真实执行；P4 扩展委派；P5 接入账户；P6 完成恢复和资源冲突；P7 做整体验收。未来阶段不视为本轮开发授权。

2026-10-16 用户调整：首个真实 Agent 使用 **Codex app-server**。P2 先验证其正式协议的离线子集；P3 再接通真实进程。Echidna 自身运行时的桥接留作后续目标，不修改或复制其他仓库的 AgentLoop。

同日追加要求：自由交流并保持通用，后续接入自己的 Agent。当前 P3a 实现通用 RuntimeBridge/RuntimeCodec、角色自由对话、Codex stdio/独立登录入口；先以离线子进程和不同协议适配器验收，再验证真实二进制的未登录握手。P3 的真实推理、路线分叉与跨进程恢复不因此标为完成。

## 技术方案

| 部分 | 第一版选择 | 原因与限制 |
| --- | --- | --- |
| Web | React + TypeScript + Vite | 便于拆分人物、菜单、详情和局部事件记录；当前原型只作为视觉与交互基线 |
| 画布 | DOM/SVG + Pointer Events | 直接复用现有空间交互；文字可选择，记录可访问；先测量再决定是否引入大型画布引擎 |
| 本地编排 | 一个 Node.js/TypeScript 服务 | 共享类型、管理多个独立运行时会话；不引入额外分布式服务 |
| 通信 | HTTP 命令 + SSE 事件 | 命令响应与连续事实流分离，支持游标补齐；不需要双向实时编辑 |
| 存储 | SQLite 存编排记录与视图，文件目录存大材料 | 单用户本地事务、索引和恢复；运行时自身记录仍由运行时持有 |
| 首个运行时 | Codex app-server，经固定 RuntimeBridge 接入 | 使用正式线程/回合/事件 API；P2 只有协议夹具，P3 先核对目标二进制 Schema 与握手 |
| 认证 | 运行时或固定接入适配器持有凭据 | 浏览器只持有账户引用和状态；按一个已验证协议逐个接入 |
| 检查 | 单元测试 + 集成故障夹具 + Playwright | 投影、准入、持久化与真实 UI 分层验证 |

依赖在相应阶段引入并锁定版本。P2 使用 Node 24 自带的 `node:sqlite`，没有新增 npm 依赖。Codex 通过子进程边界接入，不引入其内部 crate 或复制 AgentLoop。

## P0 · 建仓与设计基线

交付：独立私有仓库、README、设计原则、原型、当前选定素材、来源清单、开发计划、架构与验收文档、无需原宿主的本地预览。

门槛：全新检出可运行预览；三个场景入口可用；原型和素材哈希可核对；仓库不包含账户、令牌、运行会话或其他仓库的内部开发记录。

## P1 · 可维护的离线画布

依赖：P0。

2026-10-16：本地实现与验收已完成，详见 `STATUS.md` 和 `P1_OFFLINE_CANVAS.md`。后续阶段尚未开始。

1. 建立最小应用构建与检查命令；只创建实际消费的模块，不预建空包。
2. 将人物、工具栏、菜单、对话详情、局部记录、连线和项目档案从单文件中拆出；保持现有默认配色与角色。
3. 建立纯事件投影器与独立 ViewState；复用同一套投影生成实时与历史视图。
4. 实现画布新建/切换/复制、平移缩放、拖动、框选、草稿图形、临时连线、手工撤销重做；复制只复制视图与来源引用。
5. 从原型提取确定性夹具，覆盖流式参数、并行回传、没有摘要的轮次、事后评估和有限采纳。
6. 本地保存视图、主题与草稿；演示会话与真实执行数据分开标识。

验收：三个主要场景可完整运行；历史前缀不泄漏未来事件；节点落位后不因新增记录重排；图形编辑不改事实；320px、736px、1024px 可操作；关闭动效后状态仍清楚。完成 A01–A04、A11 的离线部分。

## P2 · 事件契约与运行时桥接验证

依赖：P1。此阶段只使用 Mock/Fixture，不发送真实 Provider 请求。

2026-10-16：Codex 正式文档映射、固定 RuntimeBridge 协议夹具、本地持久化与故障验证已完成；实际二进制和真实调用留在 P3。见 `P2_CODEX_BRIDGE.md` 与 `STATUS.md`。

1. 核对 Codex app-server 的线程、回合、中断、事件、历史及账户接口，产出官方文档映射和待验证的二进制兼容缺口。
2. 在当前仓库实现一个固定的 RuntimeBridge 与 Fixture 实现；命令和事件在边界完成版本与结构校验。
3. 为协调器建立持久化命令表、全局事件游标、运行时来源引用及去重键；确认后才向 Web 发布 durable 事件。
4. 完成单个 Agent 的创建、任务绑定、流式输出、工具参数与结果投影；内部 Provider 消息、原始凭据不进入 Web 协议。
5. 验证事件缺口、重复、乱序、版本不支持、进程退出和提交后断线；未知状态必须可见。

验收：同一 Fixture 从不同传输分块输入，得到相同投影；重复命令不会再次派发；已接收命令但结果未知时不能当作未执行。完成 A05、A09 的桥接夹具。

停止点：P2 仅建立协议夹具与本地持久化，不宣称真实 Codex 已接通。P3 前核对实际版本的生成 Schema、初始化握手和所需通知；不抓取 CLI stderr、猜测工具结束或直接读取内部历史文件。其他运行时的修改不在本阶段默认授权内。

## P3 · 一个真实 Agent 的完整路径

依赖：P2 的桥接证据。先使用一个显式配置的协议，不同时接入多个厂商。

**P3a 当前交付：** 自由输入、独立草稿与对话记录；运行时中立的协调器/存储边界；Codex 0.149.0 目标 Schema、隔离握手、专属登录入口和模型目录；只读启动、未知效果与无重发行为的子进程 Fixture。最低限度登录接口提前用于首个 Codex 适配，不代表完成 P5 的账户生命周期与多接入。详见 `P3A_RUNTIME_CHAT.md`。后续仍需操作者完成独立登录，按本阶段要求进行有界真实任务验收。

2026-10-17 修复：按目标版本识别 18 类已知 item 的消费字段，新增原生工具与当前进度通知回归；用户追加图片／浏览网页的画布预览，作为可选 tool.finished.preview 投影实现。没有启动 P4 委派或 P6 恢复，没有隐式开放搜索／图像生成能力。验证与具体限制见 STATUS。

同日用户明确调整当前默认值：HTTP-only、完整文件／网络访问、live 网页搜索、无需执行审批；附加提示仅保留工具用法，新增限制须先同意。取代上述验证阶段的只读默认值，不改写历史样本与已有线程。

同日追加实现：逐条对话的用户发起上下文分叉与 Markdown 回复。原生 thread/fork 精确继承已结束的回合前缀；点击用户消息在发送前分叉并预填草稿，点击回复在回合终态后分叉。完整离线验收包括实际 Codex 二进制连接 loopback 模拟模型检查请求上下文，以及 HTTP 去重、SQLite 重载、嵌套来源、未知状态和不重放。无新远程推理；浏览器视觉与真实模型效果尚未追加验收，不扩展 P4。

2026-10-19 用户追加并验证创建时自动连接 Codex、同时选择项目档案并使用对应 cwd，画布用自适应虚线区域组织人物与档案。菜单／弹窗外部收起、简洁网页主题卡及透明顶栏属于同轮交互修正。具体证据与限制见 STATUS，不扩大 AI 委派、Resume 或全画布自动布局范围。

同日用户明确追加创建配置自动生成、harness 原生模型／认证／人格配置，以及独立 MCP 图标跨项目连线绑定。当前范围只支持已接入 Codex 和地址式 Streamable HTTP；静态密钥由专用本地存储持有，绑定引用版本化。配置切换在已知空闲时保留上下文并建立新原生 Session，不称为旧会话 Resume。真实二进制与本地模型／MCP 夹具验证和实屏证据见 STATUS；不据此标记完整 P5 账户生命周期、P6 恢复或真实 Docker 操作完成。

1. 启动产品拥有的 Codex app-server 进程，通过 `initialize` / `initialized` 握手后 `thread/start`、`turn/start`；记录实际返回的 thread/session ID，不推测身份对应关系。角色外观只影响 Web。
2. 展示实际返回的摘要、回答、工具调用与回执；缺失字段明确显示未返回，不补造候选项。
3. 对话补充形成新输入；任务改向通过显式命令产生新路线，保存原输入快照与分叉来源。
4. 区分暂停后续采样、取消请求、执行器确认、连接丢失和结果未知；连接断开不重发工具。
5. 由 Web 发起一个有界、只读的端到端任务；真实模型验证需单独明确授权并记录所用配置引用、请求数、用量和限制。

验收：从用户任务到工具回执再到最终回答有完整来源；暂停仍可接收已有工具结果；改向保留旧路线；浏览器断开后不制造取消或完成。完成 A01、A02、A05、A09 的真实单会话部分。

## P4 · AI 委派、临时协作与有限采纳

P3b 补充：固定 canvas-v2 标注／来源查询工具及用户发起的原生上下文分叉属于 P3；分叉离线契约已验证，真实模型效果、浏览器视觉和重启 Resume 尚待单独验证。它们不提供 AI 创建子 Agent 的能力，不代表 P4 已开始。

依赖：P3。最多先验证一个父 Agent 与两个子 Agent，不引入通用工作流引擎。

1. 给具备编排职责的 Agent 注入版本化操作契约、正式 Tool Specs、当前任务和有界团队摘要；不要求模型理解网页或像素坐标。

3. 创建前原子检查共享并发、总创建数、层级和预算；无权限或额度不足时不创建伪角色、不派发执行。
4. 子会话只接收选定材料、任务、完成条件与结果接收者；保持独立的工具和 Provider 状态。

验收：重复创建请求返回同一已知结果；父子记录不串线；第三次超额创建在派发前拒绝，已派发工具仍能回传；子 Agent 返回不自动等于父 Agent 认可。完成 A03、A06、A07、A10。

## P5 · 账户、模型与能力设置

依赖：P3；可以在 P4 完成后开展，先保证编排不依赖多账户。

1. 先接通一个明确支持的 API Key 接入，再按实际运行时支持逐个接入订阅登录；两者共享同一 Agent 配置入口。
2. 登录由产品自己发起，凭据保存在本地服务或运行时的专属存储；Web、画布文件和导出仅持有引用。
3. 区分本地已登录、服务端授权、模型目录、模型选择、能力声明和实际调用成功。供应商头像不决定能力。
4. 模型、人格/工作偏好更新在下一轮输入快照生效；不修改旧请求的配置记录。
5. 区分准入上限、Provider 用量、可查询额度和实际费用；未返回费用时显示未提供。过期、限流、撤销失败均保留明确状态。

验收：凭据不出现在浏览器存储、日志、导出或仓库；离线 Fixture 不发送真实凭据；一个 Provider 失败不会回退到其他账户或付费通道。完成 A08。

同日追加交互优化及可见修改位置：目录树、多文件窗口内存草稿、默认只读预览、编辑器排版控制，以及所选版本对上一条记录／当前草稿的逐行增删差异。继续使用既有文件和历史接口，不扩展资源编排或恢复范围。

同日用户追加档案项目切换：支持本地绝对路径和最近项目，持久化当前选择、切换文件与修改路线、保护未保存草稿；明确项目来源，防止切换中的保存串写。该选择独立于已有 Agent 工作目录，不扩展运行时项目重绑定或多 Agent 资源隔离。

依赖：P4 与 P5；恢复语义从 P2 起设计，此阶段完成跨重启验收。

1. 项目档案接入真实文件和不可变材料引用；显示版本、读取来源、建议基础版本与差异。
2. 多写入任务先使用隔离工作副本；未隔离的同一资源由协调器串行归属，提交时核对基础版本。
3. 分离浏览器刷新、事件流重连、协调器重启和运行时退出；分别恢复视图、补齐事实和核对执行。
4. 在协调器确认命令后、运行时派发后、收到回执前以及发布事件前注入故障。恢复仅补齐已知记录，未知效果保留并要求按运行时约定处理。
5. 导出脱敏的任务/材料/来源与视图；导入历史不自动启动任务。

验收：两个建议基于同一旧文件时不静默覆盖；浏览器/服务重启不重复执行工具或累计用量；进程失联时不能把工作副本、预算占用或资源归属提前释放。完成 A09、A12。

3. 完成键盘、可访问名称、减少动态效果、主题对比及窄屏菜单；角色不在视野内时仍可操作。
4. 在新建项目与已有项目各走完一轮完整流程，记录通过项与限制；有真实副作用的验收另行授权。
5. 固定发布版本、数据版本和升级检查；提供本地安装、数据路径、备份与恢复说明。

验收：A01–A12 全部有对应证据；计划性能指标在目标机器实测，未达标不写成已支持；不存在模拟登录被当作真实接入的界面。

## 最小开发单元与依赖

```text
P0 基线 → P1 离线画布 → P2 桥接验证 → P3 单 Agent
                                          ↓
                                   P4 委派与协作
                                          ↓
                                   P5 账户与能力
                                          ↓
                                   P6 恢复与资源
                                          ↓
                                   P7 首版验收
```

每个阶段拆成 1–3 天可验收的纵向变更；这表示拆分尺度，不是交付承诺。只有 P2 验证现有接口、P3 获得真实运行数据后，才按实际工作量安排日历。

## 需要持续跟踪的具体风险

| 风险 | 验证阶段 | 处理方式 |
| --- | --- | --- |
| 运行时缺少机器事件/控制接口 | P2 | 用接口映射证明缺口；单独提案，不解析终端文案 |
| 某协议没有候选决策或可见摘要 | P2/P3 | 只呈现确实返回的字段，保留缺失状态 |
| 协调器与运行时无法做跨进程原子提交 | P2/P6 | 持久化命令关联与回执核对，保留未知，不承诺普遍 exactly-once |
| 订阅登录成功但无调用资格 | P5 | 账户、目录、能力与调用验收分别记录 |
| 多 Agent 改同一文件 | P6 | 隔离工作副本或串行归属，加基础版本冲突检查 |
| 长任务画面过密或文本遮挡 | P1/P7 | 语义缩放、按需展开、可见区域加载，先测量 |
| 设计人物素材无法用于目标发行范围 | P7 前 | 保留来源与归属；发布前确认授权或替换角色资源 |
