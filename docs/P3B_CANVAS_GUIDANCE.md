## 图形与来源

每个回合保留独立身份，内部按实际事件顺序追加输入、标注、工具和回复。参考最新截图采用疏朗分层片段：上方是任务、材料与真实引用短标签，中间是无框衬线标题，下方保留真正提交的候选方向。判断不再套用大菱形或卡片；手工画笔仍保留原图形。工具使用圆形终端落点、有限的命令字面预览和独立状态角标，返回状态不能取代工具身份。观察的长说明点击展开，只有结论保留有限纸面摘录。

标题上方至多常显两项既有引用，以细弧线汇入；多余引用通过数量入口进入原有详情。来源入口只导航到原记录，不追加事实或改变执行依赖。后来出现的材料在已有入口之后追加，不覆盖或移动它们。无引用不补造材料汇入，标题与工具之间也不推测执行依赖。

自然回复以气泡摘录直接展示，即使没有任何 canvas.noted，也能看到本轮实际回答。只压缩空白并截短显示，不额外调用模型或提炼不存在的判断；原文点击展开。回复按首次 responseSeq 落位，之后流式补全或新增标注不搬动它。Fixture 的角色标为离线演示，回合与回复标为固定示例；不依赖当前连接状态，也不把重复协议样例伪装成理解了新问题。

片段仅为阅读分组，不等同模型采样步骤；单片段不重复显示编号。细灰箭头只表示工具记录的先后，绿色局部分支表示所选方向，短灰虚线只表示未选项；不从判断节点穿过候选按钮向工具画推测的依赖。完整跨片段依据线默认隐藏，选中、键盘聚焦或悬停时只显示当前节点的直接引用，使用带箭头及“依据”标签的胡桃棕线。判断引用由片段侧边进入／离开，材料引用经上方及外侧绕行，小圆角避开工具、来源入口和选项。说明收在图标形式的“连线说明”里。

标注是模型明确提交的公开说明，不等于执行回执、验证证据或隐藏推理。没有候选项不补造决策，没有工具调用不显示工具步骤。同小节的工具先后线不声称已证明某候选方向派发了该工具。

节点按首次事件序号落位，材料、标题和工具分别使用独立高度。新标题通常开启新片段；当回复到达时，若当前标题为结论且尚无工具，回复在结论下方落位。此后到达的工具另开片段，既有回复不移动。同片段新增材料或工具向右扩展；下一回合从实际宽度之后开始，并缩短运行时回合间距。高度按已出现内容与引用范围计算，不为纯对话预留整片工具区。历史前缀不包含未来标注。自动跟随最新步骤，手工漫游仍关闭跟随。

工具紧接无候选项的回复／公开记录；只有当前已存在的决策需要给候选按钮留出空间。若工具先出现、决策后出现，决策另开小节，不把旧工具下移。显示全部同时缩小上下边距，使矮窗口里的文字保持可读；仍由用户明确触发，不主动重置已有视角。

终端调用用“终端命令 01”等短名称。详情分别展示命令、工作目录、输出与来源/回执，保留可选择的等宽原文；长 ID 和原始输出不占主画布。其他工具保留实际工具标题，不猜测命令的任务含义。

点选节点只打开该节点的详情，选择首先显示公开依据和真实候选方向，命令直接展开参数与输出。依据和后续引用可逐个导航，选中态由同一个临时面板状态持有，画布同步聚焦直接引用；“查看整轮记录”保留整轮入口。切到更早的历史前缀时，不显示尚未出现的节点。显示全部按运行时记录的实际高度计算边界。

## 预填能力

`contracts/canvas.ts` 保存当前 canvas-v2 指导、两个固定 Tool Specs 与输入 Schema。Codex 线程启动时同时交付 developerInstructions 和 dynamicTools；输入快照记录 canvasContract 版本。旧 canvas-v1 快照仍可读，不重写既有线程或事件。自己的 Agent 后续可暴露同一工具并产出通用 canvas.noted 事件，无需实现 Codex 消息。

2026-10-17 用户调整：developerInstructions 与 Tool description 仅保留参数、返回值、引用语法和调用示例；移除任务、人格、工作步骤、表达风格及其他行为指导，不要求标注频率或先调用 inspect。工具本身的输入／引用契约不变。原真实样本是在旧指导下完成，不能当作精简指导已验证模型表现。

| echidna_canvas_note 字段 | 规则 |
| --- | --- |
| kind | intent / material / observation / decision / result |
| title | 1–40 字符，优先简短具体的用户语言 |
| detail | 1–1200 字符的公开说明，不能是隐藏思维 |
| refs | 最多 8 个已存在的 noteRef / toolRefs |
| options | 决策有 2–3 个唯一选项且恰好选中一个；其他类型为空 |

工具只追加标注，不执行 shell、编辑文件、创建 Agent、取消任务或授予权限。真实工具事件继续由原有协议投影。模型何时使用工具由模型决定，精简指导后的实际表现仍待观察。

## 当前来源查询 · canvas-v2

2026-10-17 的首个新样本完成了 5 条标注、1 个双分支选择和 2 条只读命令，但一次观察把第二条命令读到的内容关联到第一条命令。仅在发布标注后返回 toolRefs 会产生引用发现延迟，不能把这次完成称为来源语义全部正确。

新增固定只读工具 `echidna_canvas_inspect({})`，供模型在工具返回后、提交观察或选择之前查询当前回合来源。返回 toolRefs、最多 8 条最近命令的 commandPreview（前 120 字符）、运行时原始 status/实际 exitCode，以及最多 8 条最近标注的 noteRef/title/kind。来源跟随已准入的回合持有；不接受会话、路径或其他选择参数，不能查看其他 Agent 或上一回合。

查询通过与标注相同的 started 身份/工具名/参数配对、来源序号与持久化确认路径，但不产生 canvas.noted 节点、执行回执或验证事实。先提交成功的源帧再回复，不增加新的事实存储或工具注册层。标注也返回相同来源提示，保留原有 noteRef/toolRefs 字段。

指导要求按命令预览匹配实际收到的输出，再引用精确 toolRef；不得把上一条已知命令当作新观察的依据。查询解决来源发现时机，不自动证明模型理解、结论成立或引用语义正确。新工具只对新建 canvas-v2 线程可用，不能伪装成给旧线程追加能力。

补充两类对照示例：检查反馈改变下一次选择时，引用实际观察和先前决策；普通问候或直接查询不强行生成分支。明确要求候选项是可选的行动方向，而不是全部都要执行的清单。示例中的版本标签仅为虚构教学材料，不能复制成当前任务事实。模型不负责坐标、SVG 或网页操作，前端负责版式；无法获得 toolRef 时不得猜测引用，后续标注使用工具实际返回的标识。指导更新在服务下次启动后影响新建的运行时线程，当前运行服务与既有线程保留原指导，历史不会被重写。

本轮没有内部思维抓取或独立模型评审。分层布局及节点详情使用离线前缀/拥挤小节/静态渲染检查；当前来源查询使用真实子进程夹具验证。复杂的工具依赖、分支派发关系和真实子 Agent 布局需要相应的明确运行时事实，不能由当前五种标注或时间顺序推断。真实样本及浏览器限制见 STATUS.md。

## 确认与失败

Codex 0.149.0 的 dynamicTools 是实验接口，initialize 明确开启 experimentalApi。客户端只处理固定 item/tool/call，不增加通用注册层或自动审批。

先校验输入和已有引用，并核对实际 started item 的身份、工具名和参数。SQLite 成功提交并发布后才回复 success、noteRef 和当前 toolRefs。参数或引用错误明确返回失败；持久化失败仍中断连接并保持未知。拒绝的标注不占来源序号，重复身份不能覆盖原记录。标注工具的 started/completed 只保留来源，不制造命令执行回执。
