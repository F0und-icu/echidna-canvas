## P3a 已实现的对话入口

- 创建 Agent 默认自动连接当前本地 harness；下拉可明确选择已接入的 Codex，或显式创建离线画布示例。头像独立于 harness，不按角色名猜运行时。当前不提供未接入运行时的占位选项。连接失败保留表单并显示原因，不降级为离线角色。
- 模型目录来自该 harness 的实际返回，优先使用其声明的默认模型；没有默认值但只有一个时可自动选中，其他情况手动选择。配置项按该模型声明的支持项生成，名称／任务可自动填入，形象与描述按需修改。未登录时可选浏览器、设备码或 API Key 认证并刷新状态。创建请求携带所选 harnessId，服务准入前核对当前 backend；旧 v1 请求仍可省略此字段。确认后把实际 Session 附到当前画布并打开独立对话；创建本身不向模型发送任务，也不启动回合。画笔落点用于新角色的位置，已有角色再次打开保持位置。
- 创建结果未知时保留原 commandId 和请求、锁定表单，重新连接后可核对同一结果；不会再次派发已准入的创建。此核对只返回已有命令状态，不代表未知 Session 已恢复。关闭面板后可从「Agent 连接」查看持久化的命令派发记录。
- 真实创建同时选择本地项目档案。先登记规范化路径，再提交带 projectRoot 的创建；实际 Codex cwd 必须匹配，分支继承来源根。确认后人物与同根档案位于同一自适应虚线区域，同根复用档案，不同项目独立显示。已有命令核对不重新要求目录存在；更改档案选择不重绑定已有 Agent。
- 点击运行时角色展开独立对话。消息原文（含换行和首尾空格）作为新回合输入，不覆盖旧快照；仅空白输入在边界拒绝。
- Enter 发送，Shift+Enter 换行，输入法组合过程中的 Enter 不发送。每个 Agent 独立保存草稿；确认后仅清除此次提交且未再修改的草稿。结果未知时保留草稿，不自动重发。
- 历史面板只显示该前缀的对话且禁止派发。普通回复在画布显示有限摘录，并按首次响应事件固定坐标；不是新的模型摘要或 canvas.noted。Fixture 的角色、回合与回复均保留离线／固定示例标记，尚未连接时也不丢失来源。
- 运行时标题上方的局部依据入口只导航到既有当前回合节点，不生成事实副本；最多常显两项，其余进入完整依据详情。若回复首次出现时已有结论且没有工具，回复放在其下方，后到工具另开片段，已有位置不变。
- backend 声明 chat / interrupt / login 能力、模型目录与账户状态；头像和模型名称不参与能力推断。登录 URL 只允许 HTTPS，凭据由专属运行时保管。
- 2026-10-17 用户指定 Codex 默认完整文件／网络访问、实时网页搜索、无需执行审批、模型连接 HTTP-only。应用附加提示词仅含两个画布工具用法；任务与工作偏好保留在画布配置中，不追加到模型 developerInstructions。旧线程的历史提示不改写，新规则适用于新建线程。
- 通用来源是 backendId + storeId + sessionRef + streamId + sourceSeq；可选 executionRef 保留运行时真实返回的独立执行身份。旧 P2 的 threadId 只作为历史来源兼容。
- 用量明确标注 thread-total 时取最新累计值，不累加每轮累计数；普通采样用量仍按其原有语义累计。缺失费用不推算。

- 未完成回合的运行时连接中断时，即使没有工具调用也显示结果待核对，部分文字标为回复未完成。原因来自该历史前缀中的 connection.lost；已完成的旧回合不因后续断线改成生成中。最近运行时错误通知可显示原文，不从文案推断执行结果。
- 工具真实完成后，可选 preview 在画布追加图像／网页主题卡并连到原工具。图像可打开查看；网页主题从实际 URL 路径派生，显示域名，点击打开原链接，不声称已嵌入或加载成功。画布不常显来源按钮，来源入口保留在「图片与网页」详情和工具记录内。没有 URL 就不猜地址，没有本地图片就显示无法预览。图片当前内容不等于不可变证据；搜索结束不等于查到有效结果。历史前缀、复制视图和移动节点不重发工具或重新浏览网页。

回复卡片、对话及完整回复详情使用 Markdown，支持 GFM 表格与代码块。画布以固定高度显示摘录，通过「展开回复」查看完整内容；链接可独立打开。存储的原文、流式响应来源与历史前缀不变，原始 HTML 不执行。

菜单、详情侧栏、连线说明与项目选择器点击外部关闭，点击另一控件同时保留其操作。原生文件／图片模态仅在遮罩上完成点击时请求关闭；内部点击和内部开始的拖动不触发。文件关闭仍经过未保存草稿检查，图片模态不关闭所属详情。左上菜单／画布标题背景透明；文本输入焦点保留单层边框提示。

## Harness 认证与独立 MCP 接入（2026-10-19）

`BackendStatus.models[].settings` 只声明当前模型支持的原生选项与默认值，`authentication` 声明可用认证方法及当前模式。`AgentConfig.harnessSettings` 保存非秘密设置；自由文本 personality 沿用画布备注语义，不追加开发者提示。`POST /api/runtime/login` 的专用 authentication 联合类型接收 API Key／browser／device-code，旧 `{version:1}` 仍走既有设备码流程。API Key 认证返回确认；浏览器／设备码返回运行时给出的授权链接，确认不代表调用额度或模型任务已通过。

「接入与 MCP」独立保存 Docker／通用 MCP、HTTP(S) 地址与认证定义。`GET/POST /api/runtime/mcp-connections` 读取元数据／创建新版本；secret 仅在专用提交中出现，输入提交后清空，列表与版本内容不返回秘密。修改基于 baseRevision，冲突可见。保留已有密钥要求地址和认证定义相同；换地址需重新填写。配置的 id + revision 是绑定引用，历史版本不随编辑覆盖。

画布只保存 connectionIds 与 `positions['mcp:' + id]`。连线到运行时角色打开绑定面板，由 `agent.mcp.configure` 的独立命令明确应用到该 Agent；同一节点可连多个项目，不隐式共享聊天。配置在已知空闲时切换，原记录保留，MCP 工具加载不产生模型回合或工具重放。底层使用完整原生回合前缀／既有局部快照新建 Session，并追加 session.mcp.configured，所有旧回执继续保留原 Session 来源。创建与普通分支也可带／继承固定版本的接入引用。

带版本的连线表示已确认的配置绑定。`GET /api/runtime/mcp-status?agentId=...` 读取该已加载 Session 的实际目录、初始化与认证状态，失败分类可见；工具为零不冒充连通。`POST /api/runtime/mcp-login` 只允许对已绑定的 OAuth 接入调用 native mcpServer/oauth/login，返回链接供用户完成授权。应用静态认证和外部登录相互独立。元数据修改、图标拖动／复制、历史回看和页面刷新不派发配置命令；历史视图需主动返回实时后才可应用。

当前支持地址式 Streamable HTTP 接入及 Codex 的原生认证接口；未提供 stdio 命令安装器、MCP 市场或通用插件注册中心。共享地址／密钥不等于资源写入隔离，Docker 操作能力仍由所选网关实际暴露。

## 项目档案文件窗口（2026-10-18）

画布档案管理员和菜单打开同一个原生模态窗口，提供目录浏览、文本编辑、显式保存和版本对照；模态焦点阻止背后的画布快捷键误操作。初始目录来自服务的项目配置；用户可通过「切换项目」输入本地绝对路径或选择最近项目，切换文件树、档案角色的项目名称及该项目修改路线。已有 Agent 会话继续使用原工作目录；档案切换不派发运行时命令，无需调用模型。这里展示当前磁盘文件，不是事件回放时的材料快照，不声称 Agent 已读取或采纳。

单用户服务的当前档案项目与最近目录保存在 `files.sqlite`，文件和历史仍按 canonical root + path 隔离。切换项目前检查当前窗口全部未保存草稿，可继续编辑或明确放弃后切换；失败不会提前清掉旧项目草稿。关闭后再打开／刷新恢复所选项目，重新选回旧项目可查看原有记录。无效、不可访问或私有目录显示错误并保留原选择；已选目录后来被移除时不静默换成默认目录，仍可从切换入口选择其他项目。当前不提供系统文件夹选择器，使用路径输入和最近目录。

`GET/POST /api/runtime/file-projects` 读取／切换项目，`POST /api/runtime/file-projects/register` 登记目录并返回 canonical root，不改变当前全局选择；沿用本机 Session、Host、Origin 和 JSON 校验。文件、目录、历史和保存请求携带 URI 编码的 `X-Echidna-Project`。新请求使用 `X-Echidna-Project-Bound: true`，只操作该已登记根，因此不同项目窗口互不影响；无此标记的旧客户端仍核对当前选择，保存接收完整正文后再次核对，跨切换返回 409。画布节点携带其项目来源，迟到元数据响应不覆盖新项目。凭据／内部目录过滤同样作用于指定根，不能用切根绕过。

目录按需展开为树，保留其他目录与当前层级；长名保留尾部区分信息，完整路径可查看，侧栏可调宽度。筛选只作用于已加载目录并明确标注范围；方向键导航，窄屏使用可收起的导航抽屉。搜索输入使用容器的单层 focus-within 边框，保留键盘焦点提示，不叠加输入框轮廓。单击文件默认只读预览，点击「编辑文件」才允许修改。CodeMirror 提供行号、代码高亮、查找、12–22px 字号及换行控制，默认 15px；Markdown 默认使用阅读视图，可切换源码。未覆盖的语言以纯文本显示。

打开过的文件通过标签切换，草稿和编辑状态按路径保留在当前模态窗口的内存中。切换文件不自动保存、不重新读取已打开的文件；显式刷新文件才读取磁盘。关闭窗口／转到画布时检查所有文件的未保存修改，允许继续编辑或明确放弃；离开页面也触发浏览器防丢失提示。草稿不写入 Workspace、浏览器持久化或导出。

修改记录默认选择最新版本，以「上一条已记录快照 → 所选版本」显示逐行差异，标出新旧行号、增加／删除行、增删行数及差异片段。替换显示为删除旧行并增加新行，保留默认九色配色。提供前后差异跳转、全文／改动上下文切换、空白字符和末尾无换行标记，也可改为「所选版本 → 当前文件／未保存草稿」比较。首次读取没有前驱，只显示完整快照，不把首次读取伪装成文件创建；两个内容相同的版本明确显示一致。这里只描述快照之间的文本差异，不推断期间的每次编辑或 Git 血缘。画布节点传入的 revisionId 使用同一比较规则；弹窗路线图默认收起，可展开选择版本，正文保持可滚动。

追加：碧翠丝作为画布文件路线的根节点，连接各文件及版本节点。文件顺序按首次留档固定；版本从旧到新按持久化 ID 连接，首次读取与后续观察使用读取节点，手动保存使用铅笔节点。实线对应后一个手动保存记录，虚线对应后一个读取观察；这描述记录先后，不推测未记录的分支、外部编辑者或 Git 血缘。最新节点标为「最新记录」，不冒充实时磁盘状态。点击节点传递 path + revisionId，在文件窗口精确展开版本；保存后路线追加节点，不移动既有节点。

角色及其文件／版本路线共用画布世界坐标和父容器，拖动根角色整体移动；旧画布位置保留在 `positions['project-archive']`，绑定项目按 `positions['project-archive:' + root]` 保存手动位置，不写执行事件。历史元数据接口 `GET /api/runtime/file-history` 读取指定项目的 path、revision ID、hash、来源和时间，不返回文件内容或创建读取记录。刷新后重新读取服务元数据，浏览器仅保存位置与项目成员；迟到元数据按根和持久化 ID 合并，不覆盖刚保存的节点。文件窗口的版本图支持横向滚动，并定位所选版本；窗口内部滚动不会平移背后的画布。

打开 UTF-8 文本时保存 path + SHA256 + 内容快照；重复读取不重复留档。保存基于已读取的 hash，冲突返回 409 并保留草稿；显式读取新磁盘版本后可与草稿对照再编辑保存。通过同目录临时文件替换，避免直接截断目标文件。手动保存和读取观察分别记来源；历史版本只在本地文件档案中保存，不作为编排执行事件，也不加入浏览器画布存储或导出。

修改记录从首次读取开始，外部变化仅在下一次读取／保存检查时记录，不追溯 Git 历史、不猜测外部修改者。失败保持可见，没有自动保存或自动重试；保存结果未确认时读取磁盘与记录核对。文件系统替换与 SQLite 留档不是跨资源事务；写入后留档失败会返回错误，不能当成整体未执行。当前无文件创建／删除、多进程锁或自动监视器，不宣称解决 P6 的并发资源归属。

HTTP 文件接口沿用 loopback Host、Origin、会话与 JSON 校验。目录遍历、符号链接、内部记录和常见凭据路径在文件服务边界拒绝；UTF-8 类型及 1 MiB 上限只约束此浏览编辑入口，不改变运行时执行能力。

## 已实现的历史上下文分叉

片段处「发送并开支线」表达另一种想法，创建独立 Session 与画布分支，不修改原路线。Agent 对话顶部可以切换继续／纠正与新想法支线；支线边界在用户选择方向时固定。当前任务运行中可以先编辑纠正草稿并请求打断，收到运行时 interrupted 终态后才允许发送新的纠正。回合中断确认不等于工具取消确认；没有结束回执的工具仍为 unknown，后续输入不会重放它。

片段详情直接提供按来源 eventId 保存的消息草稿；点击「从此片段发送」或 Enter 创建分支后将原文发送到新 Agent，再打开其独立对话。只有创建确认后才发新消息，发送确认后才清除草稿。未知结果保留命令身份和草稿，不自动重发；同一面板核对继续使用既有 commandId。关闭详情后仍可找到已创建角色与派发记录。该入口不会继续原路线。

2026-10-17 追加：片段标注／已回传工具节点提供 `side=at`，eventId 绑定该节点真实事件；分支只复用此前完整回合与当前回合截至节点的公开记录快照。当前局部快照由正式 thread/inject_items 加入新线程，不伪装成任意 item 的原生截断，也不包含隐藏 reasoning 或后续内容。界面及原始命令明确保留此模式；完整回合的 before/after 契约不变。详见 `LONG_TASK_ACCEPTANCE.md`。

- 每条用户消息旁的分支按钮从发送前开始，原消息预填为新分支草稿；每条 Agent 回复旁的按钮从本回合结束后开始。回复未结束时按钮说明需要等待终态；没有自动发送草稿。
- 命令 `agent.fork`：version=1、commandId、sourceAgentId、roundId、side=before/after、eventId。eventId 指已保存的用户输入／回合终态事件，不能用浏览器重新编号的游标代替。
- 新 Agent 仅继承所选前缀，后续对话不进入上下文；源对话保持原样且可继续。画布用细绿分支线和独立人物表示，继承聊天可返回来源。第一条输入前为空上下文，嵌套分叉同样按已继承前缀计算。
- 原生分叉确认校验精确前缀；失败或结果未知时显示原因，同一 commandId 返回既有结果，不重发工具或自动开启新回合。分支记录重载后仍可查看；旧真实会话 Resume 尚未接入。
- 这项功能隔离会话上下文；共享文件、工作目录和外部服务状态不回滚。运行时主动读取文件获得的信息不等于继承聊天。

## 事件信封

必要字段：`schema_version`、`event_id`、`workspace_id`、`workspace_seq`、`agent_id`、`session_id`、`type`、`payload`。涉及路线、轮次、调用和命令时附各自的稳定 ID。

来源字段保留 `origin_kind`、`source_session_id`、`source_event_id/receipt_ref` 和投影版本。流式片段另带来源内有序编号；只在来源确实提供时间时记录来源时间，不把本地接收时间当作执行时间。

本原型的 `model.completed` 表示可见模型输出结束，不表示工具、任务或研究结论完成。生产事件名称与运行时映射在 P2 确认；不直接强制改写核心事件类型。

## 事件族与显示

| 事件族 | 状态与图形 |
| --- | --- |
| round / summary / response | 一次采样的局部区域；分块原位补全；无摘要不补造 |
| decision / assessment | 当时的选择与事后评估分开，明确依据和后续引用 |
| tool prepared / arguments / dispatched / started | 参数未完整、校验、派发和实际运行各自可辨认 |
| tool result / failed / cancellation | 真实结果与回执；取消请求不等于取消确认 |
| agent create / delegation | 创建回执、任务接收、工作、回传、采纳分别显示 |
| route proposed / applied | 采用后才追加路线，保留来源事件前缀与输入快照 |
| connection / reconciliation | 连接错误不改变执行事实；未知有独立标记 |
| usage / admission | 实际用量和准入拒绝分开；缺失费用不推算为实际费用 |

线条语义固定为响应先后、依据引用、执行依赖、反馈、任务派发和路线纠正；顺序线不能被解释为已证明因果。手工线默认属于草稿。

## AI 的固定工具入口

AI 操作任务和协作对象，不需要模拟鼠标。由协调器完成落位、连线与局部布局。以下工具以正式 Tool Specs 注入运行时，各有 `Use when`、`Do not use when`、`Prefer`、`Produces` 和精确参数/结果 Schema。

| 工具 | 输入重点 | 输出重点 | 边界 |
| --- | --- | --- | --- |
| `workspace.inspect` | 任务/Agent 过滤、游标、条目上限 | 当前团队状态、可访问材料引用、限制 | 只返回有界摘要，不复制所有会话 |
| `agent.spawn` | 任务、完成条件、选定材料、接收者、预算引用、command_id | 创建状态、agent_id、session_ref、任务接收状态 | 原子准入；无额度时拒绝且无执行回执 |
| `agent.send` | 接收者、消息、材料引用、command_id | 交付状态、消息引用 | 消息不自动赋予对方上下文与权限 |
| `agent.result` | delegation_id、游标 | 进行状态或结果引用、来源、限制 | 尚未返回不能生成“无问题”结果 |
| `route.propose` | 选定来源、修改目标、依据 | 待采用建议引用 | 不覆盖历史，也不自动撤回旧执行 |

子 Agent 不通过创建图形绕过配额。工具执行入口和 UI 命令共用同一个准入所有者；暴露工具是可用性声明，实际执行仍由现有运行时与编排边界负责。

## 能力预填

每个会话启动快照包含：`contract_version`、`agent_id`、职责、任务、完成条件、工具能力版本、材料引用、消息接收者与共享预算。`model_config_ref` 和 `account_ref` 只指向配置，不含凭据。

提示中说明如何查看团队、何时委派、如何等待与引用结果，以及哪些状态不等价；工具 Schema 才是可执行操作的正式定义。恢复/压缩后从当前配置重建同一契约，不依赖历史聊天里的一次说明。

## 输入与纠正

每次采样绑定不可变 `InputSnapshot`，含任务/工作偏好/模型配置引用/材料版本/能力版本/上游来源。已有轮次不因设置变化而改写。

从历史发起对话时固定 `source_agent`、`source_route`、`source_node`、`source_event_seq`；后台新事件不改变分叉起点。采用建议后，旧路线暂停的是后续采样，已有工具仍可回传。

## 恢复与幂等

已知同一 `command_id` 返回同一持久化命令记录。重复事件按稳定来源去重。事件连接恢复可以补齐记录，不能把命令当作事件重新发送。

创建与工具派发跨越进程边界时存在未知窗口：协调器记录与运行时回执需要核对。没有可核对的结果就保留 `outcome_unknown`；这不等于失败、取消、未执行或可以自动重试。

## 复制、导出与素材

复制画布默认复制视图、草稿与历史来源引用，执行身份不重用为新任务。若用户另行启动新任务，必须重新创建会话和命令 ID。导出不包含凭据、Provider 隐式状态或其他 Agent 未共享的上下文。

外观资源只声明角色与动作帧，不声明模型身份、能力、官方背书或实际执行状态。角色缺帧时采用明确的静态形象；不补造尚未收到的执行状态。
